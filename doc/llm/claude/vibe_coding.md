## vibe coding
### 人应该做的事
1. 制定要求
    * 制定边界，制定规范，制定要求（`CLAUDE.md`）
    * 制定hook (`.claude/settings.json` / `SubAgent`) 及权限(`.claude/settings.json` / `SubAgent` / `skills`)
    * 制定流程，制定任务 (`SDD`)
2. 验收代码
    * 检查生成的是否在边界内（错误处理，异常，潜在风险）
    * 有没有遵循项目规范，风格，一致性
    * 是否能满足业务需求
    * 是否能按照你进行实现
    * 检查代码的质量

### 上下文/memory
1. 把每次重复需要告诉大模型的写入到`CLAUDE.md`/`Agent.md` 中。可以把部分提示词放到`SubAgent`或`skill`（按需加载）
2. 写入项目的大纲，命名规范，路径规范，入参出参要求，错误处理，各个路径下处理能内容。
3. memory不是一开始就能写得完美，需要一步一步的调试修改制定。
4. 制定规范时应该尽可能具体而是不是模糊的，如 "代码简洁"，"好阅读"，"结构清晰"
5. 由于上下文有限，把容易出错的写入。基本不会出错的条目不用特别提醒
6. 当一些编写限制时经常/偶尔不能拦截时，可以补充这样做的目的/场景（大模型现在的能力已具备理解场景）
7. 通过模版可以让大模型通过样例进行符合预期的生成

## 常见的AI场景
1. 程序员：代码生成 ,代码优化 ，重构 ，review
2. 运维：devops生成 (dockerfile ，makefile , jenkins ,k8s yaml)
3. 产品经理： 需求文档，代码解释文档，通过代码生成原始需求
4. 程序员/运维：线上问题排查 (CLI或 Headless)
