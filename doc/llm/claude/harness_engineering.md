# Harness Engineering 总结文档
Harness 包含约束、工具、文档和反馈循环，用来让 Agent 保持高效和方向正确（claude code 正在实现这个目标）
* Harness Engineering 的系统负责做四件事：
  * 约束 AI Agent 能做什么（架构边界、依赖规则）；
  * 告知 Agent 应该做什么（上下文工程、文档）；
  * 验证 Agent 做对了没有（测试、Lint、CI 验证）；
  * 纠正 Agent 出错时的行为（反馈循环、自我修复机制）。
Harness Engineering 的四个主要调控杠杆是：
  * 系统提示（System Prompt）
  * 工具/MCP/hook
  * 上下文
  * Sub-agents。


## 1. 核心范式理解
### 1.1 LLM 不确定性本质
* 最大问题不是随机性（代码风格差异、变量名变化）
* 而是**语义理解漂移**：同一需求不同阶段可能理解不同，导致错误输出（如将会员数据当订单数据处理）
* 因此需要**规范化、冻结决策、可控输出**

---

## 2. Constraint System（规则系统）
* Agent.md / CLAUDE.md / Subagent 用于约束行为
    * 限定模型的输入、输出、可操作范围
* 核心作用：**控制 LLM 不偏离既定决策**
* 注意：
    * Constraint 写错 → 模型会稳定地产生错误
    * Constraint 只是“注释” → 不生效，需要强制执行机制（Validation）

---

## 3. Harness 核心构成
### 3.1 状态机（State Machine）
* 定义清晰阶段：`spec → task → plan → code`
* 每个状态只执行对应的操作
* 阶段之间不可随意回退，回退必须受控（Controlled Backtracking）
  * 有系统停止，不是又大模型停止修改
  * 当如果task有问题，需要回退plan跟code，task确定完后重新生成plan，code

### 3.2 控制流（Control Flow）
* 系统负责状态转换、输入输出流向
* 防止模型跳步、修改已冻结的决策

### 3.3 工具管理（Tool / Skill / MCP /hook）
* 模型不自由选择工具
* 系统限定工具使用范围（只读/可写/Shell操作等）
* 避免调用错误工具导致输出错误

### 3.4 冻结决策（SDD）
* 冻结需求、方案、执行计划
* 保证每一步输入确定，输出可控
* 使 LLM 成为“工具函数（Function）”，而不是主控程序。意思就是返回确定的结果，中间如何实现可以不同

#### 3.4.1 SDD的目的
* **决策层**：由 SDD 冻结的文档负责
    * `spec.md`：需求分析（产品经理角度）
    * `task.md`：技术方案（架构师角度）
    * `plan.md`：执行步骤（开发者角度）
* **执行层**：LLM 根据冻结的决策文档完成具体任务（代码、文档生成等）
* 好处：
    * 避免上下文污染
    * 避免半路改需求导致返工
    * 降低搜索空间（减少反复思考）

---

## 4. LLM 在 Harness 中的角色
* **工具函数（Function）**，按需执行任务
* 特征：
    * 输入确定 → 输出范围可控
    * 不负责决策、状态管理
    * 避免自由推理导致的上下文漂移
---

## 5. 常见失败原因

| 序号 | 失败原因            | 核心问题                  |
| -- | --------------- | --------------------- |
| 1  | 错误在早期阶段（spec）引入 | 冻结不严格，决策被污染           |
| 2  | Constraint 没生效  | 模型只把规则当注释，缺乏校验        |
| 3  | Tool 选择权在模型手里   | 模型调错工具 → 输出错误         |
| 4  | SDD 未冻结         | 模型可随意改需求 → 上下文漂移 → 返工 |

---

## 6. 最佳实践思路（工程级）

1. **状态机设计**
    * 明确阶段
    * 每个阶段只做对应任务
    * 阶段回退受控

2. **约束系统**
    * Constraint 明确且可执行
    * 必要时加 Validation 层
    * 工具权限严格管理

3. **冻结决策**
    * SDD 冻结需求、方案、计划
    * 任何改动必须通过系统批准

4. **LLM 调用规范**
    * LLM = 工具函数
    * 输入确定 → 输出可控
    * 无自由决策

5. **可追踪、可预测**
    * 每一步操作可追踪（日志）
    * 系统行为可预测，避免自由推理失控

---

## 7. 核心总结句
> Harness Engineering = **用状态机 + 约束系统 + 控制流，将 LLM 转化为可控工具函数，确保每一步行为可预测、可执行、可验证**
